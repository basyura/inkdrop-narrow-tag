# 仕様書作成計画

## 目的

現在の narrow-tag の仕様を、参照しやすい単位で分割して `docs/specs` 配下の Markdown ファイルに日本語で記述する。

## 作成するファイル

| ファイル | 内容 |
| --- | --- |
| `docs/specs/README.md` | 概要、対応環境、構成、プラグインの有効化・無効化、各仕様書へのリンク |
| `docs/specs/tag-selector.md` | タグ取得、検索、候補選択、キーボード操作、候補なしの場合の動作 |
| `docs/specs/note-filtering.md` | タグ確定後のコマンド実行順序、待ち時間、多重選択の抑止、フォーカス制御 |
| `docs/specs/appearance.md` | ダイアログの配置、入力欄と候補一覧のサイズ、配色、スクロール |

## 記述方針

- 現在の `lib/plugin.js`、`lib/narrow-tag-dialog.js`、`styles/narrow-tag.css`、`package.json` を調査し、実装から確認できる動作と条件を記述する。
- 既存の README と v6 対応計画を参照し、対応環境の宣言と実機確認済みの範囲を区別する。
- ファイル名、コンポーネント名、コマンド名、CSS クラス名は既存コードに合わせる。
- 未実装の機能や期待する将来の動作を、現在の仕様として追加しない。
- 命名や記法以外で既存ドキュメントと実装の食い違いを発見した場合は、修正方針をユーザーに確認する。
- 仕様書から関連する実装ファイルへ相対リンクを設ける。
- 実装・依存関係・既存 README は変更しない。
